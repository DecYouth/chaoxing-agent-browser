# 超星动态页面操作细节

以下细节在 Windows、agent-browser 0.39.1 的超星 AI 阶梯闯关页面上验证过；页面或 CLI 升级后须用当前 snapshot 核对，不把旧布局当接口承诺。

## 环境与连接

1. 优先接续本任务已有命名会话与 profile。先查 `--help`、`--version` 与本版本 `skills get core`，必要时运行 `doctor --offline --quick`。
2. 缺少 CLI 且安装在用户任务范围内时，用 npm 全局安装 `agent-browser`，再运行 CLI 的 `install` 安装浏览器。仅在 npm 明确阻止该包安装脚本时，按当前 npm 提示仅允许该包的脚本；不要全局放开脚本权限。
3. Windows 全局 npm 常见结构是 `npm目录/node_modules/agent-browser/bin/agent-browser-win32-x64.exe`。附带包装脚本支持 `--bin` 或 `AGENT_BROWSER_BIN` 指定本机 native EXE。
4. 该版本 npm 的 `.cmd` 包装会把 URL 中的 `&` 交给 cmd 二次解释，造成参数截断。直接调用 native EXE；不要拼接带 URL、JS 或 ref 的 shell 命令。
5. `--auto-connect` 可能找不到内嵌浏览器。失败后使用本任务拥有的 headed 会话及独立持久化 profile，具体启动参数从当前 CLI 帮助确认。让用户在可见窗口登录，不迁移无关浏览器中的 Cookie。
6. 使用 stdin 时，Python 包装脚本继承 stdin；PowerShell 管道传递中文前设置 `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)`。若自己编写 PowerShell 包装，必须在 `$MyInvocation.ExpectingInput` 为真时显式把 `$input` 管道传给 native EXE，否则 `eval --stdin` 会执行空文本。

## 标签页与 iframe

- `tab list` 的真实标签页 ID 可能是 `t11`，不能当作第 11 页或用旧下标猜测。选页命令以本版本 core guide 为准。
- 课程主页面常有多层跨域 iframe。先用 snapshot 中的 iframe ref 切换并观察；如 snapshot 显示子页而 eval 的 `location.href` 仍是顶层，说明这次命令没有落在预期文档。
- 只读获取当前实际 iframe `src`，在同一登录会话中新开该地址。核对任务标题与账号。不得复制旧账号的认证 URL 或凭记忆拼参数。
- 任务卡点击后新标签页异步出现：先点击，下一轮列页并读取新页；若先在旧页上等待“提交答案”，会出现假超时。
- 更换账号后，旧报告标签页仍可能显示原账号已完成状态。回到当前课程入口/任务列表验证身份并取得新链接，旧页只作历史证据。

## 等待与本题定位

- 生成反馈通常需要数秒到数十秒，最后总结可能超过一分钟。单次等待不超过 30 秒，采用“等待—观察—继续”的方式。
- 页面保留完整对话，body 中出现“提交答案”“太棒啦”不等于新状态已经就绪。优先检查新 snapshot 中当前可见、enabled 的答题/结束控件，以及题干或对话末尾是否变化。
- `document.body.innerText.slice(-6500)` 仅用于快速读取末尾；题干较长或截断时扩大读取范围。不能以截断文本直接答题。
- 若需过滤快照以减少历史 disabled 控件，仍要保留错误、反馈、对话框和当前按钮；有疑问读取未过滤 snapshot。
- 提交后不确定结果时先观察，不重复点击。ref 随页面变化可能过期，每次页面变化后重新取 ref。

## 计算与异常记录

- 固定字长下区分真值、机器数、无符号、原码、反码、补码。负数原码转反码只翻转数值位，符号位保持；补码在反码基础上加 1。
- 例：8 位原码 `10101100` 对应反码 `11010011`，补码 `11010100`。若平台将正确说法判错，应保留推导，不因此把“负数符号位保持不变”改成假命题。
- 补码溢出按有符号表示范围和符号规则判断，最高位进位不是独立充分条件。例：8 位 `-76 + 107 = 31` 在范围内，不溢出。
- 替换题是新题，重新检查原码/补码/反码、字长、符号、选项，不继承旧题结论。
- 建议异常记录字段：题干原文、选项、位宽及规则、独立计算、提交答案、判分原文、使用的正常 UI 动作、最终结果。不要保存账号认证参数。

## 结束与报告状态机

| 当前状态 | 下一动作 | 超时或异常后 |
| --- | --- | --- |
| AI 正在生成最后总结 | 等待唯一可用“结束任务” | 继续观察，不重交最后一题 |
| 总结完成 | 点击新 snapshot 的“结束任务” ref | 重新观察是否已出现确认框 |
| 结束确认框 | 点击框内唯一“确定” ref | 不用全文本搜索点击重复标签 |
| 结束成功、报告入口可用 | 点击新 snapshot 的报告入口 ref | 若报告已开，直接进入读取阶段 |
| 报告生成中 | 等待完整分数、知识点统计、“重新练习” | 只读等待，不再次结束或重新练习 |
| 报告完整 | 调用 `save_report.py` 并查看截图 | 检查报错与当前阶段再重采集 |

该版本确认控件曾显示为：

```text
- paragraph "确定" [ref=e123]
```

报告入口曾显示为：

```text
- generic "学习质量评估报告" [ref=e124]
```

这些只是定位示例。必须在当前 snapshot 中唯一识别，并核对确实属于当前对话框/入口。全文本 `find text 确定 --exact` 曾匹配到底层被遮挡控件；不能碰到重复文本就选第一个。

“重新练习”和分数可能先于报告正文出现。还需等待 `/本次学习共\s*\d+个知识点/`。保存脚本验证这些信号但不代替人工查看正文与截图；如果新页面更换报告结构，先检查真实文案再修改提取规则，不能删除校验来伪造成功。

## 最终证据

每账号单独使用 `outputs/账号别名/`，文件前缀由关卡顺序和简短标题构成。不要把 token 或完整登录 URL 放进文件名。保存每关完整报告、所有任务卡状态和课程完成提示；记录实际成绩，已达到要求后不自动重做追求满分。

主页的进度和弹窗可能晚于各关报告更新。若任务卡已完成但主页未更新，等待并重新读取当前入口；仍未达标就报告剩余状态。截图中若有加载遮罩或生成中内容，等页面完成后重拍并检查。
